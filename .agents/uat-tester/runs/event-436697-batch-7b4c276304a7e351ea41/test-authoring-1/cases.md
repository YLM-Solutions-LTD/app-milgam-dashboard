# Deterministic UAT coverage

The canonical end-to-end workflows remain `UAT-201` through `UAT-210` in the plan-review case set. This stage automates the locally provable portions:

- `UAT-201`: accepted synthetic capability; exact concurrent three-route POST `{}` snapshot; coherent mapped values.
- `UAT-202`: live flag is true; snapshot transport remains separate from analytical range transport.
- `UAT-203`: no affected inline styles; local SVG/classes; strict CSP source and same-origin pinned runtime.
- `UAT-204`: explicit zero, separate permit units, raw dates, equipment deduplication/conflict rejection, unavailable classification, representative volumes.
- `UAT-205`: explicit sanitized failures, last-good stale retention, abort/suppression, generation-ten winner.
- `UAT-206`: exact ready→Navigate command and parameter-free permit URL; single-flight source contract.
- `UAT-207`: RTL/LTR locale behavior, responsive/focus/live-region/logical-layout source contracts.
- `UAT-208`: negative trust matrix, private binding, revocation, late-response denial, fresh synthetic generation.
- `UAT-209`: guarded focus/busy cleanup and recoverable command failure source contract.
- `UAT-210`: traceability, flag/CSP/dependency checks, synthetic-fixture/no-JWT audit.

Exact-preview browser geometry, runtime CSP console/network behavior, render/node measurements, and approved-host revocation/command binding are not executable in test authoring and remain final-review gates.
