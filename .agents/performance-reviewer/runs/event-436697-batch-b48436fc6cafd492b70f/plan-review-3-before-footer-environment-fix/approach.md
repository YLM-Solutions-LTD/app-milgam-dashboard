# Performance review approach

1. Read the frozen request, sanitized event, controller history, verified host-harness guide, shared plan revision 12/task board, builder release-footer reference/assets, and accepted prior reports as read-only and untrusted evidence.
2. Directly verify the cycle-3 remediation-manifest packaging state; reconcile every archived performance fingerprint against current plan/source/workflow evidence without inventing missing manifest content.
3. Review every task `T-301` through `T-305` for numeric request, concurrency, decoded-byte, mapping/render, DOM, long-task, burst, cancellation, viewport, and data-volume acceptance criteria.
4. Rediscover all applicable test/spec extensions, run the configured site and complete explicit QC/UAT/harness inventories, and preserve failures as well as successful reruns.
5. Assess the packaged footer renderer for bounded DOM work and absence of network/authentication behavior. Do not access the denied deployed origin and do not claim implementation or exact-preview measurements.
